# Stateful maintenance methods

These learners implement §7 of `testbed-impl-plan.md`. They receive only `(inputs, targets, source_ids)` and a continuous update count. Their architecture adapters bind ordinary network modules; each learner contains its own update and maintenance arithmetic. Checkpoints include the optimizer, private RNG, and method history. Parameter objects and optimizer groups remain fixed during interventions.

MLP and ResNet-18 support every method below. ViT supports S&P, CBP, ReDo, SWR, and FIRE; FIRE selects only Q/K projections. The remaining ViT pairs are intentionally rejected because the plan does not establish paper evidence for those interventions.

| Method | Configuration and behavior |
|---|---|
| `shrink_perturb` | Requires an absolute schedule. Applies `retain * p + noise_scale * noise` after the optimizer step. Noise is a fresh initializer sample, standard Gaussian, or the saved initial parameter. Defaults are `retain=.999`, `noise_scale=.001`, fresh sampling, preserved optimizer state and BN buffers. |
| `cbp` | Every update, updates contribution utility and age; mature units satisfy `age > maturity_updates`. Fractional counts accumulate independently at each site. Defaults: rate `1e-4`, EMA `.99`, maturity `20`, no bias compensation, clear affected optimizer moments. |
| `redo` | Requires an absolute schedule. Recycles units whose normalized mean absolute activation is at most `threshold=.1`. A zero-activation layer is eligible. Defaults: fresh incoming weights, zero incoming bias, current-batch statistics, cleared affected moments. A larger statistics window weights batches by their feature-observation counts. |
| `swr` | Requires an absolute schedule. Scores each tensor separately after the optimizer step using magnitude or retained-gradient utility. Fraction selection uses stochastic rounding; threshold selection includes equality. Defaults: magnitude, fraction `.001`, fresh initializer samples, no EMA, preserved optimizer state. A replacement clears the whole tensor's EMA. |
| `fire` | Requires an absolute schedule. Uses ten Newton–Schulz iterations by default, spatial slices for convolutions, and the author's aspect-ratio/kernel scaling. Keeps optimizer state unless `reset_all` is explicit. Zero-norm matrices are skipped. |
| `nap` | Adds LayerNorm and removes immediately preceding affine biases; ResNet also normalizes residual sums before their activations. Projects Linear/Conv weights to their initial Frobenius radii every update by default. Exposes `init_decay`, `joint_project`, and `free` LN affine policies. Joint projection uses radius `sqrt(number of gain entries)` and rejects nonhomogeneous activations. |
| `c_chain` | Requires `buffer_size` and `reference_batch_size`. Matches a lagged predictor, with lag one by default and fixed coefficient `.1`. Uses an allocated ring of `lag+1` parameter/buffer snapshots and a reusable frozen predictor. Its bounded input buffer keeps the latest transformed input per source ID with LRU eviction. Reference sampling excludes supervised IDs. No labels or future inputs enter this buffer. |
| `optimizer_reset` | Requires an absolute schedule. Wraps ordinary backprop or a configured `base_method`; clears all optimizer state after its single update without changing weights, LR, anchors or method histories. Nested wrappers and a second full-reset policy are rejected. |

All numerical defaults above are saved, configurable testbed choices unless explicitly identified as a source setting. They are not universal paper reproduction recipes. Discrete schedules require exactly one of `at_updates: [positive, sorted, distinct, ...]` or `every_updates: positive_integer`; NaP defaults to period one if neither is supplied. Schedule positions do not restart when data distributions change.

`clear_moments` resets selected SGD/Adam/AMSGrad entries while preserving native Adam's scalar parameter step. Full reset clears scalar steps too. Unit recycling computes all masks before mutation; outgoing zeros take precedence where adjacent incoming and outgoing masks overlap. Channel normalization gains/offsets and BN running moments reset for the affected units, retaining BN's shared batch counter.

The FIRE, SWR and NaP PDFs were also extracted and checked against these operations. Direct execution against the cloned author code verified nine FIRE matrix traces (square/tall/wide, one/three/ten iterations), SWR gradient selection and full EMA reset, CBP's mature-unit selection trace `[[], [], [0]]`, ReDo's normalized score trace `[0, .75, 2.25]`, and the saved-init S&P blend. The FIRE three-iteration output is retained as a numerical fixture in `tests/test_stateful_methods.py`.

## Declared ports and scope

CBP/ReDo recycle MLP hidden layers, ResNet BasicBlock `conv1` channels consumed by `conv2`, and ViT feedforward `fc1 → GeLU → fc2` units. ResNet residual-stream outputs, shortcuts, and class units are excluded. These are explicit connections, not inferred traversal neighbors. The ResNet restriction is a port; it differs from P09's source wiring. `after_norm` selects the MLP/ResNet normalization output; ViT only permits `after_activation`, because there is no hidden-width normalization between its feedforward linears. Optional CBP bias compensation is supported only for MLPs with existing downstream biases, no dropout, and pre-activation normalization.

C-CHAIN is a supervised port of the authors' RL code. Disjoint past-input replay, a minimum sufficient history warm-up, deterministic evaluation-mode reference forwards, configurable loss-ratio windows, and continuous absolute-update scheduling are testbed conventions. It does not claim to reproduce an unavailable author SL implementation. NaP's ResNet residual-sum normalization and its MLP post-activation placement option are likewise declared adaptations. Fixed readout norms and residual projections can change predictions.

Persistent method tensors contribute to `frozen_state_bytes`; this counter includes statistics as well as frozen references, separately from optimizer state. C-CHAIN reports allocated reference-input memory separately. Maintenance timings are host wall times around the maintenance call; CUDA execution can remain asynchronous. Use synchronized full-run timing for device throughput comparisons.

Run the checks with `OMP_NUM_THREADS=1 .venv/bin/python -m pytest -q tests/test_stateful_methods.py`. They cover all supported architecture pairs, exact continuation after checkpointing (including dropout RNG), prediction-mode invariance, selected/unselected moments, projection guards, reference-buffer recency and disjointness, and intervention timing. Small ResNet/ViT update-and-restore smoke runs were also executed on an A100 using `cuda:2`.
